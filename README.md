# Пульс команди — автооновлення через GitHub Actions + Netlify

Той самий дашборд, що й раніше, тільки без Docker/Rancher. Схема проста:

1. GitHub Actions за розкладом (08:00 / 16:00 / 00:00 Київ) сам запускає
   `regenerate.py` — той тягне свіжі дані з Zammad, Supabase (розклад) і
   Simulator (чати), генерує `index.html`.
2. Той самий job комітить `index.html` і кеш назад у репозиторій.
3. Netlify стежить за репозиторієм і на кожен коміт сам оновлює сайт —
   так само, як зараз працює твій HR-портал.

Ніякого сервера, який треба тримати живим, — усе відбувається сам по собі.

## Крок 1. Створити репозиторій

На github.com → New repository → назви, наприклад, `pulse-dashboard` →
Create (Public чи Private — не важливо).

## Крок 2. Завантажити файли

Найпростіше — тим самим способом, що й портал: на сторінці репозиторію
"Add file" → "Upload files" → перетягни туди **всі** файли й папки з цієї
папки (`deploy-github/`):

- `regenerate.py`
- `pulse_template.html`
- `requirements.txt`
- `netlify.toml`
- `cache/.gitkeep`
- `.github/workflows/update-dashboard.yml`

Важливо: структуру папок (`.github/workflows/...`, `cache/...`) треба
зберегти такою, як є — GitHub при перетягуванні папки зазвичай зберігає
шлях автоматично, але звір після завантаження, що файли лежать саме в цих
підпапках, а не всі впереміш в корені.

## Крок 3. Додати секрети

Settings (репозиторію) → Secrets and variables → Actions → "New repository
secret". Додай чотири:

- `ZAMMAD_TOKEN` — твій токен Zammad.
- `SUPABASE_URL` — `https://gdiowdzzhuwfcshsrqbp.supabase.co`
- `SUPABASE_SECRET_KEY` — `sb_publishable_ejNp0_QOCb0NX8ZCbKkOsQ_I06M27Mj`
  (це публічний ключ, не секретний за суттю — але хай теж лежить тут,
  разом з рештою)
- `SIMULATOR_TOKEN` — Bearer-токен з Simulator.company. Необов'язково
  одразу; без нього просто колонка "Чат" не оновлюватиметься новими
  даними (як і в Rancher-варіанті).

Той самий екран, де в тебе вже лежать `TELEGRAM_TOKEN`/`TELEGRAM_CHAT_ID`
для бекапу порталу — процес ідентичний.

## Крок 4. Перший запуск

Actions (вкладка репозиторію) → "Оновити Пульс команди" (зліва) → "Run
workflow" → Run workflow. Перший запуск займе ~20-30 хв (рахує 40 днів з
нуля). Коли позеленіє — у репозиторії з'явиться `index.html` і заповнений
`cache/`.

Далі workflow запускатиметься сам за розкладом — нічого тиснути не треба.

## Крок 5. Підключити Netlify

Той самий спосіб, що й для порталу: netlify.com → Add new site → Import
an existing project → вибери цей репозиторій → Deploy. `netlify.toml` уже
каже Netlify віддавати `index.html` як є, нічого збирати не треба.

## Крок 6. Перевірити

Відкрий адресу, яку дав Netlify — має відкритись дашборд зі свіжими
даними. Дата в футері ("Оновлено: ...") покаже, коли він востаннє
оновлювався.

## Як оновити SIMULATOR_TOKEN, коли протухне

1. Зайди в https://sim.simulator.company, залогінься.
2. DevTools (F12) → Network → клацни щось на дашборді → знайди запит до
   `sim.simulator.company/api/1.0/...` → Headers → Authorization →
   скопіюй усе після `Bearer `.
3. Settings → Secrets and variables → Actions → `SIMULATOR_TOKEN` →
   Update → встав нове значення.
4. Нічого перезапускати не треба — наступний плановий запуск підхопить
   сам (або запусти вручну через "Run workflow", якщо не хочеш чекати).

## Відомі обмеження

- **GitHub Actions cron не гарантує запуск день-у-день секунда-в-секунду**
  — під навантаженням GitHub може затримати запуск на кілька-кільканадцять
  хвилин. Для щоденного дашборду це не критично.
- **Літній/зимовий час.** Розклад розділено на два набори по місяцях
  (03-10 — літній час, 11-02 — зимовий), тому що GitHub cron працює лише в
  UTC, а Київ двічі на рік переводить годинники. Під час самого переходу
  (кінець березня/жовтня) можлива похибка ~1 година протягом тижня —
  не критично.
- **Чати (Simulator).** Токен сесійний, згасає без попередження — див.
  розділ вище, як оновити.
- Якщо репозиторій довго (60+ днів) без жодного коміту, GitHub може сам
  вимкнути scheduled-запуски. У нашому випадку кожен запуск сам комітить
  `index.html`/кеш — тому репозиторій ніколи не буде "тихим", і це не
  повинно статись.
